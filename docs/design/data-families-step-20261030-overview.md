# 盘口、成交和单 K 线算子迁移设计

## 目标和使用场景

沿用 MA 的固定输入、字典输出和 core 生命周期。常见场景依次为：连续读取盘口价差、处理逐笔成交、逐根计算价格与技术指标、重算盘中 K 线、按既有指标计算一段历史、计算等待未来 K 线的结果，以及临时接入其他 pyta2 指标。自定义简单算子只实现 `forward`；有状态算子将可变状态放入 `_state`。

## 方案和选择

| 问题 | 方案 | 选择与原因 |
| --- | --- | --- |
| pyta2 指标 | 共用多层窗口和字段绑定基类；或各指标像 MA 一样直接组合 | 各指标直接保存自身需要的窗口和指标，数据与公式的关系一目了然；保留单独的通用桥接供其他 pyta2 指标使用。 |
| 未来结果批量输出 | 继续使用依赖各 family 的旧 batch；或在通用重放中按 `result_index` 回填 | 扩展 `forward_step_apply` 接受通用 Operator；按输入观测排列，未来结果回填锚点，末尾未成熟位置填 schema 缺失值。core 不依赖具体数据类型。 |
| 旧实现 | 全部立刻删除；或仅迁走不再被代码使用的部分 | 归档不再使用的旧窗口封装和指标封装；Bundle 尚依赖的 K 线输入、数据辅助及旧 batch 暂留，避免本轮扩大到 Bundle。 |

## 接口和状态

- 盘口 `step(*, bids, asks)` 和成交 `step(*, price, volume, side=None)` 视每条输入为新观测，向 `_step` 交固定字段，结果一律为字典。
- 单 K 线 Signal 和 Outcome 使用相同的 OHLCV 签名、`open_time`、`is_closed` 和 `is_missing`；未结束的观测由 core 统一保存快照并重算。`used_fields` 只是构造时传入的元信息。
- RSI、KDJ、均线交叉和量价指标直接保存 pyta2 指标及其实际所需的输入窗口；其他字段不保留。`volume=None` 作为缺失值。均线类型沿用 MA 的单参数集合，缺失值后的处理交给 pyta2。
- 均线交叉周期使用 `fast`、`slow` 命名，与 MACD 一致；`stride` 是交叉比较间隔。
- 影响字段选择或窗口大小的配置作为只读属性，避免运行中修改配置后与 `used_fields` 或已创建窗口不一致。
- 收益、跳空及三个简单未来结果只保存所需字段，沿用原公式和窗口内缺失语义。ATR 边界结果复用 pyta2 effect；只保存未来窗口所需 OHLC，用局部前缀视图满足 pyta2 的绝对下标接口。
- `forward_step_apply(data, operator)` 消费固定字段字典序列，接收 Signal 或 Outcome 实例。结果按本次输入中的逻辑观测排列；实例已有历史时，落在本次输入之前的锚点不出现在返回结果中。未声明 schema 时使用 object 列和 `None` 作为未成熟占位；已声明 schema 使用其各字段的 `null_value`。数据重放中盘中更新替换对应观测的结果。
- 通用 pyta2 桥接由调用者声明输入字段和历史窗口，输出使用指标 schema；不包含 KAMA 特判，也不修改 pyta2 的缺失处理。

## 查漏补缺

1. 盘中更新和确认必须从同一观测前的 `_state` 恢复；所有指标实例、窗口以及 effect 状态均只从 `_state` 读取。没有 `open_time` 时顺序由上游保证。
2. Outcome 的 `result_index` 可能小于零，批量返回必须与锚点对齐；整数输出使用 schema 的缺失哨兵，不能一律填 NaN。在线缓存按结果产生顺序保存。
3. 旧 Bundle 仍使用旧输入辅助和旧 batch，本轮不声称其已迁移。归档只针对已无代码调用的封装；不为旧接口添加兼容层。新增迁移代码需要支持状态深复制。

不在本轮编写或运行测试；静态审阅不能替代后续运行验证。

## 示例

每个示例自带输入数据且不导入其他示例文件。第一个示例集中展示均线逐条推进、盘中更新与批量计算；其余示例分别演示不同数据类型、不同指标或不同使用方式。文件名按示例命名规范的默认分级编号，按 K 线、盘口、成交、未来结果分组。旧 Bundle 示例随未迁移的实现归档，待 Bundle 迁移时再恢复对应示例。
