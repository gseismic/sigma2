# sigma2 时间参数命名规范设计

## 目标

让参数名区分技术指标的周期、两个观测位置之间的距离、算子的时序依赖与缓存容量。保持用户接口简洁，具体计算仍复用 pyta2；收益率接口和 README 已按本方案对齐，见 `PLAN-046`。

## 收益率回看参数的选择

对于 `close_t / close_(t-K) - 1`，K 表示向前相隔的观测步数，不表示计算均值的周期。

| 候选名称 | 含义和取舍 |
| --- | --- |
| `n` | 简短，但现有指标也用它表示计算周期，两种含义无法从参数名区分。 |
| `k` | 与公式一致，但脱离公式后缺少含义，容易与其他参数混淆。 |
| `period` / `periods` | 可以表示时间周期，也常用于指标周期，容易与均线的 `n` 混淆。 |
| `lookback` | 表示向后看，但可能指窗口长度，也可能指两个端点的距离。 |
| `shift` / `offset` | 表示位置移动，但单独使用时不明确方向和正负约定。 |
| `lag` | 明确使用较早观测的步数，对应 `t-lag`，采用。 |

## 规范

| 名称 | 含义 | 示例或边界 |
| --- | --- | --- |
| `n` | 单周期技术指标的参数 | `rKlineMA(n=5)`；也用于已有单周期 ATR、RSI、Boll 等。具体公式、预热和历史依赖由指标定义。 |
| `lag` | 当前观测与所使用的过去观测之间的逻辑步数 | `close_t / close_(t-lag) - 1`；对收益率算子要求正整数，默认 1。 |
| `n_backward` | 算子的结果位置之前所需的历史观测数 | core 生命周期元信息，由具体算法决定；不应按名称假定等于 `n` 或 `lag`。 |
| `n_forward` | 结果位置之后需要等待的观测数 | core 生命周期元信息；现有固定未来窗口的 Outcome 继续使用它作为构造参数。 |
| `history_window` | 向下游指标提供的输入历史长度 | 现有 pyta2 桥接使用此名；它与指标计算周期及输出缓存是不同概念。 |
| `buffer_size` | 保留的输出结果数量 | `0` 不缓存、`-1` 无限缓存；不是指标的计算周期或输入窗口。 |

`n` 不只用于简单均值。例如 SMA 的 `n=5` 使用当前值及此前 4 个值；EMA 的 `n` 还决定平滑系数，递推状态可能受到更早数据影响。其他指标的首次可用时点应以其自身实现和 `min_periods` 为准，不能假设均为 `n` 条。

`lag=5` 指当前位置与参考位置相隔 5 次逻辑观测：`t` 与 `t-5`。计算这种端点收益率跨越 6 个时间位置，但公式只读取两个端点；中间缺失不自动改变端点定义。单 K 线按 K 线观测推进，Bundle 按共同截面推进；它不是自然时间，`open_time` 不会自动补齐缺失位置。

对简单的 `lag` 步收益率，`n_backward=lag`、`n_forward=0`，所以 `min_periods=lag+1`。一般情况下 `min_periods=n_backward+1+n_forward`；实际缺失数据或指标自身预热仍可能让某一步的输出为 NaN。

多个指标周期应按业务含义区分，例如现有 MACD 的 `fast`、`slow`、`signal`，或 ATR 边界算子的 `atr_n`。具有明确角色的不同周期不应只用难以辨认的数字编号。现有 KDJ 的 `n1`、`n2`、`n3` 尚未按此规则改名，具体名称应结合其公式单独确定。

同一业务参数在逐条算子、批量入口和实例属性中使用同一个名称。`n` 和 `lag` 不作为彼此的别名；新增相同概念的算子时复用上述命名。如果未来一个业务参数和实际结果所需的前后观测步数不一致，应分别命名和说明，不能将其当作同一个值。

## 已对齐的收益率接口

逐条算子、批量入口及对应实例属性统一使用 `lag`：

```python
rKlineReturn(lag=5)
KlineReturn(data, lag=5)

rKlineBundleReturnRank(lag=5)
KlineBundleReturnRank(data, lag=5)
```

技术指标的 `n`、core 的 `n_backward` / `n_forward` 及现有 Outcome 的 `n_forward` 保持各自含义。按用户要求，收益率接口不保留旧的 `n` 别名。

## 检查

1. **概念**：SMA 的 `n=5` 是技术指标周期，收益率的 `lag=5` 是两个端点相隔的步数，名称不同。
2. **时间边界**：`lag=1` 使用上一逻辑位置；`lag=5` 使用第 5 个之前的位置。没有提交的时点不会被自动推断，应由上游保持时间轴。
3. **生命周期**：`lag` 是算法配置，`n_backward`、`n_forward` 和 `min_periods` 描述结果所需的数据位置，不为所有算法建立固定换算关系。
