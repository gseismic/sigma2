# 代码审查问题修复设计

## 目标

修复审查指出的生命周期配置、schema 缓存、依赖版本、批量错误处理、盘口价差和极端权重问题。沿用固定输入、字典输出，以及 `has_missing=False` 时由上游保证数据有效的约定。

## 方案比较

| 问题 | 方案 | 选择与原因 |
| --- | --- | --- |
| 窗口参数 | 支持运行中修改并重建状态 | 需要定义历史和缓存迁移，不符合当前生命周期。 |
| 窗口参数 | 读取公开属性，禁止修改 | 构造时配置与实际窗口一致，采用。 |
| schema 缓存 | 所有结果都使用 object 列 | 行为统一，但常规数值结果丢失原 dtype。 |
| schema 缓存 | 仅多维值或缺失值为 None 的列使用 object | 保持常规数值 dtype，并保留数组和可空值，采用。 |
| 输出格式 | 重放完成后检查 | 参数错误会消耗输入并改变算子状态，不采用。 |
| 输出格式 | 重放前通过实际输出转换入口检查 | 覆盖支持的类型及可选依赖，避免另维护一份格式列表，采用。 |
| 盘口价差 | 要求列表已按价格排序 | 需要调用方保证顺序，原接口没有声明该约定。 |
| 盘口价差 | 从买卖档中分别取最高和最低价 | 直接满足最优价差定义，采用。 |
| 加权平均 | 总是使用高精度运算 | 普通输入会有额外计算开销。 |
| 加权平均 | 常规情况使用浮点，极小时计算精确分数 | 只在权重比例或价格贡献过小时承担精确运算开销，采用。 |

## 接口和数值约定

- `n_backward`、`n_forward`、`buffer_size` 在构造时确定，以只读属性提供；改变配置需要创建新实例。
- schema 为非标量或缺失值为 `None` 的输出列使用 object 存储；标量数值列继续使用 schema 的 dtype。批量与在线采用同一规则。
- 批量重放在消费数据前检查 `return_type` 和所需的输出转换依赖；参数错误不会推进传入实例。
- pyta2 依赖固定至 `65071a84099c30a4d9476c327232da7c057b2caa`，该提交已将审查中提到的 `rROC` 等指标迁移到 `n_backward` 接口。
- 盘口输入为档位序列，计算最高 bid 与最低 ask；任一侧为空时输出 NaN，不依赖输入顺序。
- 固定权重在构造时复制并只保留原始正权重成分；`weights` 属性返回这些原始值的副本，计算时按总权重归一化。这样即使比例小到不能直接表示，也不会把原权重变成零。
- 对每个成分，通常按归一化浮点权重计算贡献；当权重比例或价格贡献小于浮点正常数范围时，用 `Fraction` 累计这些贡献，再与常规结果合并并转换为浮点。动态市值沿用相同处理，也能保留多个极小贡献的合计。输出仍为浮点，受浮点舍入和可表示范围限制。
- 数据源负责在有缺失或无效数据时设置 `has_missing=True`；本次不增加完整截面的逐项有效性检查。

## 三轮检查

1. **接口与状态**：只读参数与构造时固定的窗口和缓存保持一致；用户可读取属性与元信息。
2. **缓存与错误**：可空标量、多维输出在线和批量均可按对象保存；不支持的返回格式在重放前失败。
3. **边界与数值**：零权重不参与计算；原始正权重始终保留；极小占比不先舍入为零，盘口价格不依赖档位顺序。
