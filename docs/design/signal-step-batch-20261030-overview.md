# Signal 的逐条重放与批量结果

- 创建时间：2026-10-30 06:08 CST
- 范围：补充 MA 和 MACD 批量入口、通用 Signal 重放方法及当前示例；其他指标和 Outcome 的批量迁移不在本轮范围。
- 依据：当前固定字段 `step` 契约，以及 `pyta2/pyta2/base/utils.py` 中的逐步计算和结果整理方式。

## 场景

1. 按时间顺序计算多根已结束 K 线的 MA 或 MACD。
2. 对同一时点的未结束观测进行更新并最终确认，输出中只保留该观测最新结果。
3. 调用者可选择字典、列表或表格等结果格式，也可获取算子元信息。
4. 空输入返回有 schema 字段的空结果；未声明 schema 的简单自定义 Signal 也可重放。
5. 上游可以通过生成器提供记录，无需先复制全部输入。

## 方案比较

| 问题 | 方案 | 选择 |
| --- | --- | --- |
| 批量计算 | 直接复用 pyta2 `forward_rolling_apply` | 它要求 pyta2 算子及 `rolling`，不适用于 sigma2；不采用。 |
| 批量计算 | 新建 Signal，逐条调用 `step` | 与在线公式及生命周期一致；采用。 |
| 输入 | 字典、旧对象、字段映射等多种兼容格式 | 规则复杂且旧格式非当前契约；不采用。 |
| 输入 | 每条记录是可展开为 `step(**record)` 的映射 | 固定输入格式直观，可用于 K 线及其他 Signal；采用。 |
| 输出收集 | 各指标分别维护列表及格式转换 | 逻辑重复；不采用。 |
| 输出收集 | 借鉴 pyta2，使用 `VectorTable` 和 `get_outputs` | 统一收集与格式转换；采用。 |
| 更新同一观测 | 每次输入都追加一行 | 会把多次更新误作多条观测；不采用。 |
| 更新同一观测 | 依据 Signal 的 `g_index` 替换最后一行 | 与 core 的观测语义一致；采用。 |

## 契约

- 通用 `forward_step_apply(data, signal, *, return_type="dict", return_meta_info=False)` 逐条接收映射并调用 `signal.step(**record)`；从传入的 Signal 当前状态继续，不隐式重置。它不依赖行情 family，也不处理 Outcome 的未来结果回填。
- 表格优先采用算子 schema 的 dtype；没有 schema 时首条输出字段按 object 类型建立列，不根据首值推断数值类型。schema 已声明时空输入保留空列。
- 新观测追加，未结束观测更新时替换尾行；输出按逻辑观测排列，最后未结束的观测保留最后一次预览。元信息来自重放结束后的实例。
- `KlineMA` 与 `KlineMACD` 构造 `buffer_size=0` 的对应 Signal，然后使用同一重放方法；默认为 schema 字段名到数组的字典，也可选择 pyta2 `get_outputs` 支持的结果格式和元信息。
- 输入记录遵守固定 `step` 签名；标的、额外元数据及旧 `KlineBar` 需要上游整理，批量接口不引入字段映射或兼容层。
- 用户报错的 `01_kline_batch.py` 更新为固定字段字典，使用 `ma`、`dif`、`dea`、`macd` 字段和 `full_name` 元信息。
- 其他指标、通用旧 batch 和 Outcome 尚未迁移；本轮声明 schema 的批量结果只覆盖标量字段。结果格式、时间顺序、缺失值及并发语义由当前 Signal 和 pyta2 输出工具共同决定。

## 三轮检查

1. **接口**：单个输入符合对应 `step` 签名，字典输出字段与在线结果一致；用户可选其他批量格式。
2. **状态与更新**：只创建一个 Signal，内部 `step` 负责快照，表格只根据索引追加或替换；不保存重复的观测状态。
3. **边界**：声明 schema 的空结果保留字段；未声明 schema 不用首个整数推断 dtype；未迁移模块和旧输入对象的支持不被暗示。
