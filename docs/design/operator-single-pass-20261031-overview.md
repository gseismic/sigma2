# 算子单向推进与失败锁定

- 创建时间：2026-10-31 14:23 CST
- 状态：按本设计实施。
- 范围：core、各数据类型入口、现有算子、批量重放、示例及使用说明。

## 目标与场景

每次 `step()` 处理一个新的观测。单 K 线调用方负责提供已经确定的行情；多次传入同一时点也按多次观测处理。单条 Signal 的结果属于当前观测，Outcome 的结果属于固定未来期之前的锚点。

算子只负责自己的指标计算和所需历史。历史修订、重新计算或计算失败后，调用方创建新实例并从可靠数据重放。

## 方案比较与决定

| 问题 | 方案 | 决定 |
| --- | --- | --- |
| 最后一条观测 | 继续保存快照并重算 | 需要管理检查点及输出替换，不采用。 |
| 最后一条观测 | 每次 `step()` 推进新观测 | 生命周期单一，采用。 |
| 观测身份 | core 检查重复时间 | 增加时间状态且不能覆盖没有时间的输入，不采用。 |
| 观测身份 | 上游负责顺序和去重 | core 不保存观测标识，采用。 |
| 重置 | 初始状态深复制，或各算子实现重置钩子 | 增加共享状态约束或各算子样板，不采用。 |
| 重置 | 新建实例并重放 | 类直接持有指标与窗口，采用。 |
| 逐条入口 | 数据类型实现 `step()` 并调用内部 `_step()` | 需要额外的内部入口，不采用。 |
| 逐条入口 | `rOperator.step()` 统一推进，数据类型整理输入并调用 `super().step()` | 生命周期只有一个入口，采用。 |
| 失败处理 | 抛异常后继续允许使用实例 | 子指标和缓存可能已部分改变，不采用。 |
| 失败处理 | 计算前设置失败标记，完全成功后清除 | 防止误用且不要求子类编写恢复逻辑，采用。 |

## 契约

- `rOperator.step()` 在调用 `forward()` 前推进 `g_index`。首次调用期间的索引为 0；`result_index = g_index - n_forward`。
- 进入计算前设置 `_faulted`；只有 `forward()`、输出字段检查和在线缓存写入全部成功才清除。任何阶段的异常保留失效标记，之后的 `step()` 报错，提示新建实例并重放。失败实例的索引、缓存和子对象不保证可用，不执行回滚。
- 数据类型入口在调用 `super().step()` 前完成自身输入整理；在进入 core 前被拒绝的输入不会锁定实例。`forward()` 是计算钩子，调用方使用 `step()`。
- 不提供 `reset()`、`_state`、状态快照、观测标识检查或 `is_closed`；`open_time` 可作为普通输入传给计算钩子。`is_missing` 保留缺失 K 线语义。
- 各指标直接持有自己的子指标、输入窗口和递推数值。用户自定义算子可以使用普通实例属性，不要求可深复制。
- 批量重放每次成功输入追加一行；Outcome 仍按 `result_index` 回填历史锚点。继续已有实例时，只返回本次输入范围。批量整理发生在逐条推进之后，异常不自动撤销已处理的输入。
- 保留 schema、输出字段检查、可空或多维输出的 object 缓存、输出缓存容量及元信息。实例不保证并发或重入安全。

## 三轮检查

1. **接口**：单 K 线和 Bundle 不检查重复时间；盘口和成交也使用同一推进入口；旧 `is_closed` 和 `reset()` 调用需要上游调整。
2. **计算与失败**：`forward()` 看到已推进的索引；子指标、结果检查或缓存写入失败均锁定实例；调用数据类型入口前的参数错误不推进计算。
3. **批量与数据**：每个成功观测对应一行；Outcome 继续回填并保留未成熟尾部；缺失值、schema dtype、空输入和从已有实例续放的处理保持各自语义。
