## 目标与方案比较

调用者需要了解 `step()` 的参数和常见输入结构；库作者需要用少量普通字典描述动态 symbol、具名字段和序列元素。该描述用于查询，不参与行情校验或转换。

| 方案 | 优点 | 代价 | 决定 |
| --- | --- | --- | --- |
| 保留现有递归 schema 语言 | 结构细节和声明错误可统一检查 | 声明冗长，维护一套独立类型词汇和校验器 | 不采用。 |
| 仅使用签名和说明文字 | 实现最少 | 无法直接组织多层字段 | 不单独采用。 |
| 字典列表加可选嵌套描述 | 定义接近用户意图，允许保留必要结构 | 嵌套内容的准确性由作者维护 | **采用**。 |

## 声明与查询

`input_schema_details` 是列表，每项是描述一个 `step()` 参数的字典，使用 `name`、`type` 和 `description` 等普通字段。`type` 是说明性的字符串，不限制为封闭的类型词汇。未声明的参数返回 `{"type": "unknown"}`。

对于嵌套结构，按需使用三个可选字段：`fields` 是具名字段字典列表；`values` 描述动态 key 映射的值；`items` 描述序列的元素。它们只是组织描述的约定，不要求每个节点都声明所有字段，也不自动校验实际输入。嵌套字段可写 `required`；省略表示未知，与值是否可为 `None` 是不同问题。

例如 K 线排名的 bundle：

```python
input_schema_details = [
    {
        "name": "bundle",
        "type": "mapping",
        "description": "key 是 symbol 字符串，value 是该 symbol 的 K 线",
        "values": {
            "type": "mapping",
            "fields": [
                {"name": "close", "type": "number", "required": False,
                 "description": "可省略或为 None，按缺失价格处理"},
                {"name": "is_missing", "type": "bool", "required": False,
                 "description": "可省略，默认为 False"},
            ],
        },
    },
]
```

`input_schema()` 保留 `{"parameters": {参数名: 描述}}` 外层形式，按真实签名顺序返回 `kind`、`required`、存在时的 `default` 和 `schema`。`schema` 是对应声明去掉顶层 `name` 后的独立副本，嵌套列表保持原样。调用形式、必传性和默认值仅由签名决定，顶层声明不重复写 `kind`、`required` 或 `default`；默认对象保持原身份。

只做必要的顶层检查：声明是列表，列表项是含字符串 `name` 的字典；名字不能重复，必须存在于真实签名，且不与签名管理的顶层字段冲突。嵌套内容和类型词汇不做递归验证；说明是否准确由算子作者负责。查询结果的描述容器可修改，不影响类声明；声明及返回的签名默认对象应只读使用。

普通类属性继承不变：子类未声明时继承，声明后整份替换，`[]` 清空。复用父类描述时复制或展开列表并替换目标项，不原地修改共享节点。不推断注解、实例配置、成员范围或数据可得性。

## 兼容性和检查

- `input_schema_details` 从按参数名的字典改为字典列表；已有自定义声明需要迁移。`input_schema()` 外层不变，但 `schema` 的嵌套内容改为简单描述，原来读取 `fields` 字典、`nullable` 或 `enum` 的调用方需迁移。
- 第一轮使用体验：高频单 K 线和 Bundle 的 step 不变；声明只使用普通字典、列表和简短描述。
- 第二轮正确性：签名是调用规则的唯一来源；嵌套 `required` 与可空性分开，动态 symbol 不是固定字段；返回副本不修改共享声明。
- 第三轮边界：不递归校验描述、不逐条验证行情、不推断时间对齐和实例需求；保留必要的顶层名字检查，避免声明被静默遗漏。
