# PLAN-030：稳固字典式 K 线输入与字段映射

创建时间：2026-10-28 14:57 CST

## 目标与范围

按 `docs/design/step-mapping-20261028-overview.md` 和用户的后续反馈，先完成 sigma2 的公开输入接口；本计划不修改 `crypto.factor_make`。同步完成 `PLAN-029` 尚未提交的 README 和 skill 预热说明。

## 实施契约

1. 单 symbol 的 `step(bar)` 接收字典或其他只读映射；基础字段是 `open/high/low/close`，`volume`、`symbol`、时间和其他字段按算子需要确定。自定义算子可声明额外必需字段，并以映射读取扩展字段。缺失必需字段在状态推进前报错。
2. 字段映射使用 `key_map={逻辑字段: 输入字段}`，默认同名；显式映射直接读取原始输入，优先于同名键，不修改输入。映射的可选字段缺失不会变成必需。使用 `date` 与 `open_time` 演示，不把 `close` 改为其他默认名称。映射需覆盖单步、批量、窗口、自定义算子和组合子算子。
3. Bundle 字典采用 `{"bars": {symbol: bar}, ...}`，固定 `symbols` 轴，已存在 Bar 校验必需字段，缺失 symbol 推进缺失值；未知 symbol 拒绝，Bar 内若提供 symbol 须与外层键一致。`key_map` 应用于各 Bar；`bundle_key_map` 用于顶层字段。自定义 Bundle 算子可分别声明 Bar 与顶层必需字段。批量字典输入必须显式给出全集，不以首个稀疏截面推断。
4. 保留现有 `KlineBar`、`KlineBundle` 及其身份、时间校验；旧 Bundle 的缺失标的保持旧 Bar 占位类型。字典时间和 symbol 可选，按输入顺序推进，不推断时间含义。显式提供 `symbol=` 时，字典中若有 symbol 则须一致。结果对齐仍使用 `result_index`。无时间或部分时间缺失时表格使用观测序号，不伪造时间；输入的实际时间与可用时间保留在元信息中。
5. 无 volume 时窗口内部用缺失值占位；使用 volume 的算子须在推进状态前要求该字段，不使用 volume 的算子不因额外 volume 的值无法转为数字而失败。按计算依赖记录数据快照。映射信息进入元信息；`factor_names` 继续表达逻辑公式，相同公式来自不同数据源时由消费端区分来源。
6. 保持 Signal / Outcome、pyta2 schema、窗口预热和公式语义。所有 K 线和 Bundle 的具名批量入口、通用批量入口提供一致的映射方式。单 K 线批量除逐行字典序列外，也支持列式字典及 DataFrame，以便与 pyta2 使用习惯一致。
