## 范围

只调整 core、单 K 线 Signal、MA 及其直接包导出和说明；不迁移其他指标、Bundle、订单簿、成交、Outcome 的具体实现或通用 batch。移除旧兼容机制造成的未迁移入口影响如实记录。

## 步骤

1. 更新设计稿：对比可选 schema、观测标识与结束标志及初始状态自动恢复方案，明确各自边界。
2. `rOperator` 默认空状态，声明抽象 `step`，在 core 内集中管理观测标识、确认、快照、重算与重置；无 schema 的自定义信号首次输出确定缓存字段。`rSignal` 默认无预热，core 的 `rOutcome` 使用相同构造方式。
3. `rKlineSignal` 仅准备固定字段、缺失 K 线和通用生命周期参数；`rKlineMA` 将指标及窗口存入默认状态，`used_fields` 由实例参数生成，`meta_info` 由 core 统一组装。简单自定义信号只需重载 `forward`。
4. 更新 README，静态审阅代码和直接导出，修复发现的问题；按用户要求不编写或运行测试。
5. 记录结果和已知未迁移影响，向 `docs/dev/INDEX.md` 追加带分钟的计划摘要；按用户要求不提交、不推送。

## 完成条件

- core 不引用行情模块，可变计算状态集中在默认的空字典内，`forward` 和 `step` 的输出均为字典。
- core 按观测标识和结束标志统一选择推进或重算，并在状态不一致时报告错误；无标识时由上游保证顺序，未结束观测中已知的标识在后续缺省时继续保留。
- 不声明 schema、状态或重置方法的自定义 K 线信号，只重载 `forward` 即可创建和使用；缓存不会将首个整数输出固定为整数类型。
- MA 只包含一个 pyta2 指标和一个输入窗口，支持单参数 MA，`used_fields` 仅作为随构造参数变化的元信息。
- 未改变其他指标、Bundle、订单簿、成交、Outcome 具体实现和通用 batch，并说明相关旧入口尚未适配。
