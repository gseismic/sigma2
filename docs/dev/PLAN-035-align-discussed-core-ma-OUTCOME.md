## 结果

- `rOperator` 默认创建空计算状态；`step` 是抽象接口，`_step` 统一处理观测标识、确认、初始状态、快照、索引、输出缓存、重算和重置。`rSignal` 固定 `n_forward=0` 并默认无需预热。
- 简单自定义 K 线信号只需实现返回字典的 `forward`。未声明 schema 时，首次返回确定输出键，缓存列使用 object 类型；已有 schema 的算子继续按声明类型缓存。
- `rKlineSignal` 提供固定 OHLCV 签名并处理缺失 K 线，将 `open_time` 和 `is_closed` 交给 core。已知时间与结束状态不一致时报错；未结束观测中已知的时间会在中间消息缺省时间时保留。
- `rKlineMA` 保存一个 pyta2 指标和一个所选字段窗口；`used_fields` 根据实例字段设置，由 core 统一放入元信息，不参与校验。无 `_internal` 或 KAMA 特判依赖，MA 类型限于单算法参数的均线。
- 更新设计和 README；移除未迁移的 `KlineMA` 批量占位入口。未修改 pyta2 或其他数据 family 的具体实现。

## 审阅与检查

- 审阅了状态快照、末条结果替换、确认结束、重置、缺省 schema 缓存，以及数据 family 与 core 的依赖方向。core 没有导入 K 线、Bundle、订单簿或成交模块。
- 静态检查：`ruff check`、`ruff format --check` 和 `git diff --check` 通过。
- 按用户要求，本次未编写或运行测试。用户提出该要求之前的旧版临时检查已删除，其 24 项通过不能作为当前实现的验证。

## 边界

- 其他 K 线指标、Bundle、订单簿、成交、Outcome 和通用 batch 沿用旧契约，可能不能正常构造或运行。例如订单簿和成交的旧 `step` 仍调用已改为抽象接口的 `super().step(...)`；通用 batch 仍使用旧结果转换和命名接口。这些模块需后续迁移。
- 时间缺省时无法核对该次输入的观测身份；即使时间已提供，也不检查不同时间的先后顺序。上游负责数据顺序、去重，以及补齐未结束观测的确认；修改已确认的历史数据需重置并重放。
- 自动重算和重置依赖 `_state` 内对象支持深复制，且会有复制开销；当前实现未做运行验证或性能测量。计算过程中会变化的状态须全部通过 `_state` 访问，实例不保证并发或重入安全。
- 实施时按用户要求未提交或推送；用户于 2026-10-30 随后要求提交。
